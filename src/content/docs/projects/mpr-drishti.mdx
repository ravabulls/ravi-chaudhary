## At a glance

India's indirect-tax administration tracks the performance of its field offices through **Monthly Performance Reports (MPRs)**: hundreds of separate reports, published one page at a time on a login-protected internal portal. I built an end-to-end analytics solution around them. An automation tool collects every report a zone needs, and an offline dashboard turns more than 17,000 of them into validated, comparable measures. It shows how each commissionerate is doing, how the zone compares with All India, and where action is needed.

## The challenge

- **Data locked in one-at-a-time web pages.** Each report is a separate page. Reaching one means choosing year, month, tax stream, zone and commissionerate from five dropdowns, then clicking a button.
- **Volume and variety.** One zone's picture needs thousands of reports across 190 report types, 3 tax streams and 15 reporting units, and each type has its own table layout with merged headers.
- **Formats that change over time.** Several report families were redesigned around 2023-24, so years cannot simply be lined up side by side.
- **No built-in checks or comparisons.** Reports can be provisional, duplicated, misfiled or internally inconsistent. Comparing units, or the zone with the national picture, meant copying figures into spreadsheets by hand.

### Before and after

| | Before | After |
|---|---|---|
| **Collecting data** | Five dropdowns and a click for every report, every unit, every month | Choose once; reports download unattended, about 2 seconds each |
| **Organising** | Files named by the portal, saved wherever they landed | One folder tree: stream → zone → financial year → commissionerate → report |
| **Checking** | Errors found by chance, if at all | Every file checked: completeness, wrong month or unit, duplicates, totals that don't add up |
| **Comparing** | Manual spreadsheets, one report at a time | Each unit against the zone, last year and All India, across every function |
| **Reporting** | Static tables | Dashboards with conclusions and points for attention, an Excel workbook and PDF slides |

Every stage of the analytics lifecycle is covered, built from scratch: acquire, organise, validate, integrate, analyse and communicate.

<Steps>

1. **Acquire - automated collection.** The tool opens its own Edge browser window and waits while the user logs in, so it never sees or stores a password. Inside that logged-in session it chooses year, month, stream, zone and commissionerate for every report, at a steady pace. It waits for each page to settle, retries failures, pauses when the portal is slow and asks for a fresh login if the session expires.
   <Badge text="Browser automation" variant="tip" /> <Badge text="PowerShell" variant="tip" /> <Badge text="Resilient scraping" variant="tip" />

2. **Organise - one storage schema.** Every report lands in *stream / zone / financial year / commissionerate / report*. Downloads are incremental: files already present are skipped, and copies saved before the units' monthly filing deadline are refreshed automatically on a later run. Every attempt is logged (JSON Lines and CSV), and each run ends with a completeness check against what the portal listed.
   <Badge text="Data engineering" variant="tip" /> <Badge text="Incremental loads" variant="tip" /> <Badge text="Audit trail" variant="tip" />

3. **Validate - check before use.** Each file is checked for the wrong month or unit, duplicates, files resaved in Excel, missing tables and incomplete sets. Internal arithmetic is checked too: opening + received − disposed must equal closing, totals must equal the sum of their parts, and amounts must be in the right unit. Each issue says what was done and what to do.
   <Badge text="Data quality" variant="tip" /> <Badge text="Reconciliation" variant="tip" /> <Badge text="Anomaly detection" variant="tip" />

4. **Integrate - from tables to one model.** HTML report tables with merged header cells are parsed into a grid, and every figure gets a stable key (table · row path · column path). Commissionerate names are matched despite spelling variants. Old and new report formats are harmonised so years can be compared, units add up to zone totals, and All India serves as the benchmark.
   <Badge text="Parsing" variant="tip" /> <Badge text="Entity matching" variant="tip" /> <Badge text="Data modelling" variant="tip" />

5. **Analyse - measures that matter to managers.** I designed function-specific KPIs: disposal and recovery rates, growth on last year, achievement against moving targets, age profiles of pending cases, and shares and concentration (for example, the top 25 taxpayers' share). Each commissionerate is ranked against the zone, and the zone against All India.
   <Badge text="KPI design" variant="tip" /> <Badge text="Benchmarking" variant="tip" /> <Badge text="Domain analysis" variant="tip" />

6. **Communicate - conclusions, not just charts.** Eleven slide-style dashboards with hand-built charts: bars, stacked bars, lines, bullet charts, heatmap scorecards and Sankey flows. Headlines and up to six points for attention are written from the figures themselves. One click exports a consolidated Excel workbook or PDF slides.
   <Badge text="Data visualisation" variant="tip" /> <Badge text="Data storytelling" variant="tip" /> <Badge text="UX" variant="tip" />

</Steps>

## Data quality: making the numbers trustworthy

Real administrative data is messy. A large part of the work went into catching problems automatically, and into explaining every decision so that users can trust the result. Every dashboard opens with a **Validation** slide: a coverage grid shows each commissionerate and month as complete, partial, problem or missing, and an issue list sorts everything into errors, warnings and notes.

<figure class="sc-fig pj-shot">
  <img src="/projects/mpr-drishti/slide-validation.svg" alt="Mock-up of the validation slide: a coverage grid of eight units by twelve months with complete, partial, problem and missing cells, beside an issue list that says what was found and what was done. All data is invented." loading="lazy" />
  <figcaption>The Validation slide: coverage at a glance, and every issue with what the dashboard did about it. Mock-up with invented data.</figcaption>
</figure>

| Problem in the data | How it is caught | What happens |
|---|---|---|
| **Wrong file in the wrong place** | The month, unit and report code in the report header are compared with the file name and folder | The header wins; mismatches are flagged or the file is rejected |
| **Duplicates and old copies** | The same report, unit and month seen twice; identical figures under two units | The latest copy is kept; the rest are labelled |
| **Provisional data** | A report saved before the units' monthly filing deadline | Downloaded again automatically on the next run after that date |
| **Totals that don't add up** | Opening + received − disposed = closing; total = sum of parts; age buckets = pending; "for the month" ≤ "up to the month" | Flagged with the exact figures; gaps shown as "not accounted for" |
| **Wrong unit of measure** | Amounts implausibly large against the unit's whole revenue or caseload (entered in rupees, not lakh) | Left out of the totals, with a note saying why |
| **Number formatting quirks** | Odd separators, blanks, dashes and percentage columns | Numbers cleaned; percentages recalculated rather than trusted |
| **Names that vary** | Commissionerate spellings differ between reports and years | Matched while tolerating small typos, but never confusing North with South, or I with II |
| **Units reporting nothing** | A unit's report is all zeros while every other unit reports figures | Flagged as "nothing reported" and excluded from rates |
| **Distorted or incomplete benchmark** | The zone's share of All India is more than 10 times away from its median, or the All India set is incomplete | That month's All India comparison is dropped |

<Aside type="tip" title="Explainable by design">
Clicking an issue explains the problem, **what the dashboard did** about it, and **what to do**. The same log goes into the Excel workbook. The downloader does the same at collection time: each run ends with a check of what the portal listed against what is in the folder (**Complete**, **Not available yet** or **Not complete**), listing every missing report and the reason. It even tells genuine gaps apart from reports that a type of unit never files.
</Aside>

## Design decisions

Analytics tools get used when they fit the people and the environment. These choices shaped the build.

| Decision | Why | How |
|---|---|---|
| **Zero installation** | Users work on office computers where installing software is often not allowed | Both tools are single files. The downloader needs only Windows and Edge; the dashboard runs in any modern browser |
| **Human in the loop for login** | The portal uses a multi-factor login, and credentials must never be stored or automated | The user logs in; the tool waits, then works only inside the logged-in report page |
| **Privacy first** | Performance data is sensitive | The dashboard is fully offline: no server, no uploads, files read only in the browser |
| **Resumable and incremental** | Large downloads get interrupted, and portals have bad days | Skip what is already there, refresh provisional copies, retry, recover the session |
| **Explain, don't hide** | Users need to trust the numbers | Every exclusion or correction comes with a reason and a suggested action |
| **Conclusions, not just charts** | Managers need to know what to act on | Headlines and action points generated from the data, compared with last year, the zone and All India |
| **Modular dashboards** | Each function has its own reports and logic | A shared engine plus one module per function, each in its own page; new dashboards plug in |

## Results and impact

- **17,626 reports** collected and organised for one zone and All India, across 3 tax streams and 37 report months of the GST years.
- **Unattended collection** at about 2 seconds per report; later runs fetch only what is missing or provisional.
- **Every file validated**, with a completeness check after each download.
- **11 dashboards from a single folder drop**, comparing 14 commissionerates with each other, with the zone and with All India.
- **One-click Excel consolidation** per function, in the original report layout plus analysis-ready long-format data.
- **Presentation-ready PDF slides** for performance reviews.

### What it saves

A rough estimate for data collection alone: at an assumed 30 seconds per report by hand (five dropdowns, a click, then saving and filing the file), 17,626 reports come to about **147 hours**, close to four 40-hour working weeks. The downloader collects the same set unattended in roughly **10 hours** of machine time, and nobody has to sit and click. Later runs fetch only what is new or provisional, so keeping the set up to date takes minutes rather than days. Beyond collection, the bigger saving is the comparison work: figures that used to be copied into spreadsheets report by report now line up automatically across units, years and All India.

## How the project evolved

The first version of the downloader and its completeness audit were written in Python. To make the tool usable on any office computer without installing anything, I rebuilt it as a single double-click file with a guided form, live progress, automatic checks and a final completeness report. The analysis side grew the same way: a shared engine first (parsing, validation, charts, slides and Excel export), then one module per function, then a summary that combines them all.
