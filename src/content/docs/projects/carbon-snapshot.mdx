## What it can do

| Element | What it shows | How you interact |
|---|---|---|
| **Four filters** | Country, year, sector, subsector | Multi-select dropdowns; empty means "all" |
| **Summary cards** | Total emissions, number of countries, average per country | Recalculated on every change |
| **World map** | Total emissions per country, as a choropleth | Click a country to add or remove it from the filter |
| **Treemap** | Emissions by sector, then subsector, sized by volume | Click a sector to filter by it |
| **Top emitters** | The ten largest emitters for the current selection | Click a bar to toggle that country; selected countries turn red |
| **Trend line** | Emissions over time: global, one country, or one line per selected country | Follows the country filter |
| **Data table** | Every matching record, largest first, ten rows a page | Scrolls and pages; updates with the filters |
| **Reset** | Clears every selection at once | One button |

## How we built it

<Steps>

1. **Prepare the data.** Climate TRACE publishes one file per sector at country level. The team combined them into one table of country, year, sector, subsector and emissions in billion tonnes of CO₂e, then loaded it with pandas, dropped the incomplete year 2025 and the duplicate raw emissions column, and built the option lists for the four filters.

2. **Lay out the page.** Dash Bootstrap Components gave a responsive grid written in Python: a header row with the title and the reset button, a row of four filter cards, three summary cards, two rows of two charts, and a full-width table, all in the clean FLATLY theme with one central colour scheme.

3. **Draw the charts.** Plotly Express produced the choropleth map, the treemap, the bar chart and the line chart in a few lines each, with hover details, titles and colour scales set once.

4. **Make the charts clickable.** Small callbacks read where the user clicked on the map, a bar or the treemap, and add or remove that country or sector in the matching dropdown, so the charts themselves become filters.

5. **Keep everything in sync.** One main callback listens to all four filters and the reset button, filters the data once, recalculates the three figures, redraws all four charts and refreshes the table, returning everything together.

6. **Explain it.** The team presented the app and walked through its code, slide by slide, from the imports to the callbacks.

</Steps>

## Why Dash

The team compared three ways to build a data app in Python before choosing one.

| Option | What it offers | Why not (or why) |
|---|---|---|
| **Flask alone** | Full control of a web server | Every page needs hand-written HTML, CSS and JavaScript |
| **Streamlit** | The fastest start | Less control over the layout, and simpler interactivity between charts |
| **Dash** | Python for both the interface and the logic, with Plotly charts built in | **Chosen:** precise layout control and callbacks that update many charts at once |

## What the project taught

Good dashboards start from questions, not charts. Each visual here answers one: where emissions come from, what activities cause them, who the largest emitters are, and how that is changing. The most useful design decision was technical but simple: every filter and every click goes through one update function, so the figures, charts and table always describe exactly the same data. And the project was a reminder that coding, for a manager, is less about syntax than about turning a large, scattered dataset into something people can explore on their own.
