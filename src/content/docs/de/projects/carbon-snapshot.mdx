## Was es kann

| Element | Was es zeigt | Wie man interagiert |
|---|---|---|
| **Vier Filter** | Land, Jahr, Sektor, Untersektor | Mehrfachauswahl; leer bedeutet "alle" |
| **Kennzahlen** | Gesamtemissionen, Anzahl der Länder, Durchschnitt pro Land | Bei jeder Änderung neu berechnet |
| **Weltkarte** | Gesamtemissionen pro Land als Choroplethenkarte | Klick auf ein Land nimmt es in den Filter auf oder entfernt es |
| **Treemap** | Emissionen nach Sektor und Untersektor, nach Menge skaliert | Klick auf einen Sektor filtert danach |
| **Größte Emittenten** | Die zehn größten Emittenten der aktuellen Auswahl | Klick auf einen Balken schaltet das Land um; ausgewählte Länder werden rot |
| **Trendlinie** | Emissionen über die Zeit: weltweit, ein Land oder eine Linie je ausgewähltem Land | Folgt dem Länderfilter |
| **Datentabelle** | Alle passenden Datensätze, größte zuerst, zehn Zeilen pro Seite | Scrollen und blättern; aktualisiert sich mit den Filtern |
| **Zurücksetzen** | Löscht alle Auswahlen auf einmal | Eine Schaltfläche |

## Wie wir es gebaut haben

<Steps>

1. **Daten vorbereiten.** Climate TRACE veröffentlicht eine Datei pro Sektor auf Länderebene. Das Team führte sie zu einer Tabelle aus Land, Jahr, Sektor, Untersektor und Emissionen in Milliarden Tonnen CO₂e zusammen, lud sie mit pandas, entfernte das unvollständige Jahr 2025 und die doppelte Rohspalte der Emissionen und erstellte die Auswahllisten für die vier Filter.

2. **Die Seite aufbauen.** Dash Bootstrap Components lieferte ein responsives Raster, geschrieben in Python: eine Kopfzeile mit Titel und Zurücksetzen-Schaltfläche, eine Reihe mit vier Filterkarten, drei Kennzahlkarten, zwei Reihen mit je zwei Diagrammen und eine Tabelle über die volle Breite, alles im klaren FLATLY-Design mit einem zentralen Farbschema.

3. **Die Diagramme zeichnen.** Plotly Express erzeugte Choroplethenkarte, Treemap, Balken- und Liniendiagramm mit wenigen Zeilen pro Diagramm, Hover-Details, Titel und Farbskalen einmal festgelegt.

4. **Die Diagramme klickbar machen.** Kleine Callbacks lesen, wo auf Karte, Balken oder Treemap geklickt wurde, und fügen dieses Land oder diesen Sektor im passenden Filter hinzu oder entfernen ihn, sodass die Diagramme selbst zu Filtern werden.

5. **Alles synchron halten.** Ein zentraler Callback hört auf alle vier Filter und die Zurücksetzen-Schaltfläche, filtert die Daten einmal, berechnet die drei Kennzahlen neu, zeichnet alle vier Diagramme und aktualisiert die Tabelle, alles in einem Schritt.

6. **Es erklären.** Das Team präsentierte die App und ging ihren Code Folie für Folie durch, von den Imports bis zu den Callbacks.

</Steps>

## Warum Dash

Das Team verglich drei Wege, eine Daten-App in Python zu bauen, bevor es sich entschied.

| Option | Was sie bietet | Warum nicht (oder warum) |
|---|---|---|
| **Flask allein** | Volle Kontrolle über einen Webserver | Jede Seite braucht handgeschriebenes HTML, CSS und JavaScript |
| **Streamlit** | Der schnellste Einstieg | Weniger Kontrolle über das Layout und einfachere Interaktion zwischen Diagrammen |
| **Dash** | Python für Oberfläche und Logik, mit eingebauten Plotly-Diagrammen | **Gewählt:** genaue Layout-Kontrolle und Callbacks, die viele Diagramme gleichzeitig aktualisieren |

## Was das Projekt gelehrt hat

Gute Dashboards beginnen mit Fragen, nicht mit Diagrammen. Jede Darstellung hier beantwortet eine: woher die Emissionen kommen, welche Tätigkeiten sie verursachen, wer die größten Emittenten sind und wie sich das verändert. Die nützlichste Designentscheidung war technisch, aber einfach: Jeder Filter und jeder Klick läuft über eine einzige Aktualisierungsfunktion, sodass Kennzahlen, Diagramme und Tabelle immer genau dieselben Daten beschreiben. Und das Projekt hat daran erinnert, dass es beim Programmieren für eine Führungskraft weniger um Syntax geht als darum, einen großen, verstreuten Datensatz in etwas zu verwandeln, das Menschen selbst erkunden können.
